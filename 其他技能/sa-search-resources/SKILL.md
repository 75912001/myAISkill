# sa.搜索原版逻辑

## 核心标准

- 分析或复刻客户端功能时, 以 8.0 原版客户端的实际逻辑为标准. 动画顺序、声音触发、命中帧、状态切换和播放时序都归属客户端表现职责.
- 原版客户端二进制是客户端行为的最终证据. 已保存的逆向资料是优先查找的索引和中间成果; 关键结论不确定或冲突时, 回查原版二进制、资源或可复现的实际行为.
- 8.5 原版服务端源码用于确认战斗结算、协议含义、随机判定和服务端规则, 不用它替代或推翻原版客户端的表现逻辑.
- 当前 `sa.desktop` 实现只是对照和复刻目标, 不将当前实现反推成原版行为.

## 证据目录

- 已保存的 8.0 客户端逆向资料: `D:\src\github.com\sa.project\sa.desktop\旧版客户端逆向8.0`
- 8.0 原版客户端二进制与资源: `D:\csa_8.0`
- 8.5 原版服务端源码: `D:\石器资源\石器时代-解压缩使用版\石器时代8.5的服务端源码LINUX下开发\85`
- Git Bash 路径分别为 `/d/src/github.com/sa.project/sa.desktop/旧版客户端逆向8.0`, `/d/csa_8.0` 和 `/d/石器资源/石器时代-解压缩使用版/石器时代8.5的服务端源码LINUX下开发/85`.

## 证据路由

- 客户端动画, 音效, 帧时序, 界面, 移动轨迹或状态机: 先查逆向资料, 再回查原版客户端二进制和资源. 服务端仅用于解释客户端收到的事实.
- 战斗结算, 技能条件, 伤害, 随机, 协议或 AI: 先查原版服务端, 再查原版客户端如何消费结果.
- 资源 ID, 名称, 帧, 音效或配置引用: 已知文件或目录时直接定位; 未知时先查逆向资料中的索引, 再查原版资源. 仅在需要道具属性、协议或规则含义时扩展到服务端, 按实际关联建立对照链, 不强制遍历三个目录.
- 对照当前实现时, 先得出原版结论, 再阅读 `sa.desktop`; 不以当前代码补全缺失的原版证据.

## ADRN 图像索引

- 格式参考: [石器时代客户端 BIN 文件解析](https://1.shiqimod.cc/lishi/shiqi182bin.htm).
- `adrn_*.bin` 由固定 80 字节记录组成, 资源帧号可作为记录索引.
- 对当前 `D:\csa_8.0\data\adrn_136.bin` 的实测结果: 记录偏移 `76-79` 的小端无符号整数可对应 `itemset6.txt` 的 `imagenumber`.
- 批量分析前必须使用已知道具验证当前客户端版本, 不要假定其他版本采用相同字段.
- 推荐检索链路: `资源帧号 -> ADRN imagenumber -> itemset6 内部道具 ID 和详细资料`.
- 同一 `imagenumber` 可能对应多个道具, 必须保留全部匹配. 无匹配仅说明当前检索的数据表中未找到对应项; 记录客户端和数据表来源, 将未使用、数据缺失或版本不一致列为待验证原因, 不直接认定.

## 工作流程

1. 从用户请求中提取行为, 资源名称, 编号, 文件名, 扩展名, 代码符号, 函数地址, 音效 ID 或动画帧.
2. 按"证据路由"选择首查目录. 客户端功能复刻先查已有逆向资料, 避免重复反编译; 资料不足时再检查原版客户端.
3. 优先使用 `rg`. 已知文件直接查内容, 否则先按文件名或扩展名筛选, 再检索相关文件内容, 排除 `.git`. 普通文本默认按字面量匹配; 仅在用户给出正则或字面量结果不足时使用正则. 默认搜索会跳过忽略文件, 怀疑漏查时仅在相关目录补充 `--hidden --no-ignore`.
4. 根据初步结果缩小到相关目录和文件类型, 再阅读命中上下文. 对二进制记录文件路径、虚拟地址、函数或字符串交叉引用; 对源码和伪 C 记录完整路径和行号.
5. 中文无命中或上下文乱码时, 检查文本编码. `rg` 不会自动识别 GBK 或 Big5; 根据文件来源在候选文件上使用 `--encoding gbk` 或 `--encoding big5`, 并检查命中上下文是否可读. 编码未知时分别尝试并记录结果, 不改写原文件. `--text` 只取消二进制过滤, 不解决编码问题; 仅在需要搜索二进制字符串时对指定文件使用, 且不把字符串命中直接当作控制流结论.
6. 交叉验证关键结论. 把"已确认原版行为", "基于地址/调用关系的推断"和"尚缺证据"分开, 不隐去冲突.
7. 先给结论及证据位置, 多来源时按逆向资料、客户端二进制/资源和服务端源码分组, 不列空组. 功能复刻结论要额外说明客户端应保留的触发条件, 顺序, 时序和资源 ID.
8. 没有命中时, 说明实际检索的关键词、目录、文件类型及尝试过的编码, 并给出可继续尝试的同义词、编号格式、函数地址或扩展名. 区分无匹配与执行失败: `rg` 返回 1 表示无匹配, 2 表示错误, 错误不能作为无匹配证据.

## 命令约定

在 Git Bash 中执行只读命令. 典型检索方式:

```bash
reverse_root='/d/src/github.com/sa.project/sa.desktop/旧版客户端逆向8.0'
client_root='/d/csa_8.0'
server_root='/d/石器资源/石器时代-解压缩使用版/石器时代8.5的服务端源码LINUX下开发/85'

# 按证据路由选择目录, 将关键词替换为本次请求的名称或编号.
search_root="$reverse_root"
query='待检索关键词'
rg --files --glob '!.git' -- "$search_root" | rg -i --fixed-strings -- "$query"
rg -n -i --glob '!.git' --fixed-strings -- "$query" "$search_root"

# 仅在相关目录怀疑存在隐藏或被忽略文件时补查.
rg -n -i --hidden --no-ignore --glob '!.git' --fixed-strings -- "$query" "$search_root"

# 旧编码仅对已定位的候选文本使用, target_file 为其路径.
# rg -n -i --encoding gbk --fixed-strings -- "$query" "$target_file"
# rg -n -i --encoding big5 --fixed-strings -- "$query" "$target_file"
```

包含空格、中文或特殊字符的关键词和路径必须正确引用, 并使用 `--` 结束选项解析. 优先遵循项目中的 `AGENTS.md` 和更具体目录约定.

## 边界

- 默认只读检索, 不修改、移动或删除任何资源和源码.
- 不把"无文本命中"等同于"资源不存在"; 同时考虑文件名、二进制资源、编码、别名和编号格式.
- 不把现代客户端已有实现, 服务端实现或缺少证据的推断写成原版客户端事实.
- 对原版二进制, 原版资源和原版服务端源码始终保持只读. 用户明确要求继续逆向并保存产物时, 只将新产物写入 `旧版客户端逆向8.0`, 且不覆盖已有结果.
- 用户若进一步要求修改资源或代码, 先说明拟修改文件、影响和更优方案评估, 再遵循项目规则处理.
